# audio-to-text

Desktop-приложение под Windows на Python 3.10+ для пакетной расшифровки аудио в текст через локальный Whisper `small`.

Приложение поддерживает:
- пакетную обработку списка URL;
- пакетную обработку аудиофайлов из папки;
- локальное распознавание без OpenAI API;
- сохранение каждого результата в отдельный `.txt`;
- просмотр статусов и текста результата в GUI;
- отмену текущей пакетной обработки;
- автоматические логи и JSON-отчеты по пакетным запускам.

## Выбранный backend

Используется `faster-whisper`.

Почему выбран именно он:
- это наиболее практичный backend для Python GUI-приложения под Windows;
- он обычно быстрее `openai-whisper` на CPU;
- интеграция с Python проще, чем у `whisper.cpp`, если приложение строится как desktop GUI;
- модель `small` поддерживается напрямую.

Зависимости решения:
- `Python 3.10+`
- `faster-whisper`
- `requests`
- `PyInstaller` для сборки Windows `.exe`
- установленный `ffmpeg`, доступный из `PATH`

Ограничения:
- при первом использовании модель `small` может загружаться и инициализироваться дольше;
- без `ffmpeg` приложение не разрешает запуск пакетной обработки;
- качество и скорость распознавания зависят от мощности CPU и качества исходного аудио;
- сеть используется только для скачивания аудиофайлов по URL в режиме списка URL.

## Поддерживаемые форматы

- `mp3`
- `wav`
- `m4a`
- `mp4`
- `ogg`
- `flac`
- `webm`

## Режимы работы

### 1. Список URL

В этом режиме приложение:
- принимает многострочный список URL через GUI;
- умеет загрузить список URL из `.txt`;
- скачивает каждый файл отдельно;
- распознает файл локально;
- сохраняет результат в `.txt`;
- показывает отдельный статус для каждого URL.

Ошибка одного URL не останавливает весь пакет.

### 2. Папка

В этом режиме приложение:
- принимает путь к папке через GUI;
- находит все поддерживаемые файлы;
- умеет обрабатывать вложенные папки;
- распознает каждый файл локально;
- сохраняет каждый результат в отдельный `.txt`;
- показывает статус по каждому файлу.

Ошибка одного файла не останавливает весь пакет.

### 3. Один файл

Этот режим добавлен как дополнительный и не заменяет два обязательных пакетных режима.

## Установка

### 1. Установить Python

Нужен `Python 3.10` или новее.

На Windows при установке Python включите опцию добавления в `PATH`.

### 2. Создать и активировать виртуальное окружение

Все команды ниже нужно выполнять из корневой директории проекта, где находятся `app.py` и `requirements.txt`.

Пример для Windows:

```powershell
cd C:\path\to\audio-to-text
```

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### 3. Установить Python-зависимости

Команду нужно выполнять из той же корневой директории проекта и после активации виртуального окружения.

```powershell
pip install -r requirements.txt
```

### 4. Установить ffmpeg

`ffmpeg` обязателен.

Один из практичных способов на Windows:
1. Скачать сборку `ffmpeg` для Windows.
2. Распаковать архив, например в `C:\ffmpeg`.
3. Добавить `C:\ffmpeg\bin` в системный `PATH`.
4. Открыть новый терминал и проверить:

```powershell
ffmpeg -version
```

Если команда не находится, приложение при запуске покажет сообщение, что окружение не готово.

## Подготовка модели `small`

Приложение использует модель `small`.

Практически это означает:
- backend должен быть установлен корректно;
- при первом запуске распознавания модель должна быть доступна `faster-whisper`;
- если модель еще не подготовлена локально, первый запуск может занять больше времени.

Если инициализация модели не удалась, приложение покажет понятное сообщение в строке состояния окружения.

## Сборка Windows `.exe`

Для упаковки используется `PyInstaller` в режиме `onedir`.

Почему `onedir`, а не `onefile`:
- это стабильнее для `faster-whisper` и `ctranslate2`;
- проще разбирать проблемы на целевой машине;
- меньше риск, что упаковка сломает загрузку backend-зависимостей.

### Сборка через готовый скрипт

Из PowerShell в корне проекта:

```powershell
python -m venv .venv
.venv\Scripts\activate
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

Скрипт:
- обновляет `pip`;
- ставит зависимости из `requirements.txt`;
- очищает старые `build/` и `dist/`;
- запускает `PyInstaller` с файлом [audio_to_text.spec](/home/alex/projects/audio-to-text/audio_to_text.spec).

### Результат сборки

После успешной сборки основные файлы будут здесь:
- `dist\AudioToText\AudioToText.exe`
- `dist\AudioToText\_internal\...`

Для переноса на другую Windows-машину нужно копировать всю папку `dist\AudioToText`, а не только один `.exe`.

### Что должно быть на целевой Windows-машине

Даже для собранного `.exe` требуется:
- установленный `ffmpeg` в `PATH`;
- доступ к записи в папку результатов;
- достаточно места на диске для временных файлов, логов, отчетов и результатов.

### Рекомендация по распространению

Для реального использования под Windows практичнее распространять:
- архив `AudioToText.zip` с содержимым `dist\AudioToText`;
- отдельную краткую инструкцию:
  - распаковать;
  - установить `ffmpeg`;
  - запустить `AudioToText.exe`.

## Запуск тестов

Тесты написаны на встроенном `unittest`, отдельная установка `pytest` не требуется.

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

Сейчас покрыты тестами:
- сохранение и загрузка настроек;
- разбор URL-списка;
- поиск файлов в папке;
- именование и сохранение `.txt`;
- базовая логика HTTP downloader через моки;
- проверка окружения;
- пакетный worker: успешная обработка, ошибка элемента, отмена и критическая ошибка backend;
- генерация логов и JSON-отчетов.

## Как пользоваться

### Обработка списка URL

1. Выберите режим `url_list`.
2. Вставьте список URL, по одному на строку, или загрузите `.txt`.
3. Выберите язык:
   - `Auto detect`
   - `Russian`
   - `English`
4. Укажите папку результатов.
5. Нажмите `Запуск`.

### Обработка папки

1. Выберите режим `folder`.
2. Укажите папку с аудиофайлами.
3. При необходимости включите обработку вложенных папок.
4. Выберите язык.
5. Укажите папку результатов.
6. Нажмите `Запуск`.

### Дополнительные действия

В интерфейсе доступны:
- просмотр текста выбранного элемента;
- сохранение текста выбранного элемента;
- копирование текста в буфер обмена;
- сохранение всех готовых результатов в выбранную папку;
- отмена активной пакетной обработки;
- автоматическое сохранение лога пакетной обработки;
- автоматическое создание JSON-отчета по завершении пакета;
- очистка формы после завершения обработки.

## Настройки

Между запусками сохраняются:
- путь к папке для обработки;
- путь к папке результатов;
- язык по умолчанию;
- флаг обработки вложенных папок;
- политика обработки существующих `.txt`:
  - `overwrite`
  - `skip`
  - `rename`

На Windows настройки сохраняются в `%APPDATA%\AudioToText\settings.json`.

## Проверка окружения при запуске

При старте приложение проверяет:
- установлен ли `faster-whisper`;
- доступен ли `ffmpeg`;
- доступна ли папка результатов, если она уже указана;
- может ли backend инициализировать модель `small`.

Если окружение не готово:
- в нижней части окна показывается пояснение;
- кнопка запуска обработки блокируется.

## Обработка ошибок

Приложение обрабатывает:
- пустой список URL;
- некорректные URL;
- ошибки скачивания;
- неподдерживаемый `Content-Type` у URL-ответа;
- неподдерживаемые форматы;
- отсутствие файлов в папке;
- ошибки транскрибации;
- пустой результат распознавания;
- ошибки записи `.txt`;
- отсутствие `ffmpeg`;
- недоступность backend.

Ошибка конкретного URL или файла не должна останавливать остальной пакет.

## Логи и отчеты

При каждом пакетном запуске приложение создает:
- лог обработки в подпапке `logs` внутри папки результатов;
- JSON-отчет в подпапке `reports` внутри папки результатов.

Лог содержит основные события пакета:
- старт обработки;
- ошибки элементов;
- завершение элемента;
- критические ошибки backend;
- отмену обработки.

JSON-отчет содержит:
- время создания отчета;
- режим запуска;
- выбранный язык;
- список элементов;
- итоговый статус каждого элемента;
- сообщение по каждому элементу;
- путь к сохраненному `.txt`, если он был создан.
